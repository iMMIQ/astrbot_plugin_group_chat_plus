# v2.2.5 升级说明

## 本次改动

实施缓存优化的预算校准与逐次请求诊断。GLM-5.3-flash 初始文字预算采用旧估算的0.75（部署单次调用审计最低旧估算/实际usage约1.55，保留约16%余量）；其他模型保持1。按提供商、端点和实际模型隔离最近96次有效首轮样本，8次纯文字样本后采用窗口最高实际/原始估算比值乘1.2，文字系数最低0.55；任何低估样本立即增大预算。图片预留单独计算，保持原最低预留与尺寸分块估算，残差样本只能上调图片系数。共享请求按所有配置的备用模型取最保守估算。

在最终 SDK create 边界记录实际消息/工具/图片哈希、输入/缓存/输出usage、耗时、模型与错误类型，区分首轮、工具续轮及SDK调用重试。只复制本轮 SDK 客户端，复用原HTTP池而不接管关闭；备用提供商也通过请求 Context 使用同一观察器。诊断落库失败不会把成功模型响应变成错误。SDK内部HTTP重试不拆成独立记录，失败尝试没有可用usage；不将哈希前缀当成实际服务端命中率。

逐次数据写入 schema 3 的 diagnostics 表，不写 traces 或核心 provider stats，保留原 Agent 汇总避免重复计数。校准包含计数和哈希，随日志保留期清理；群重置保留无聊天内容的 token 校准样本。帧格式仍为3，不强制重建现有上下文段。输入预算32768、80%/50%换段比例、30分钟空闲阈值、人格、主动参与和戳人配置保持原状。

### v2.2.4 身份与检索改动

按房间键（平台、bot、群）和完整账号关联新旧名片。身份数据从现存成员消息恢复，不需要重新学习；忽略数字占位名、纯戳人通知、引用及私有执行记录。身份补充只进入请求尾部并计入预算，摘要输入及原文兜底保留账号和名片。

替换本轮 `get_group_message_history`：默认查询本群公开日志，结果带完整账号、发言时名片及账号别名；正文与当时名片均可匹配关键词，按任一新旧名片筛选同一账号。关键词无匹配且账号唯一时返回标注为兜底的该账号近期记录，同名多个账号不自动兜底。保留 `source=session` 查询框架当前成员档案，明确与全群日志区分，沿用原 UMO、开关和历史上限；群重置后不能借此入口读回旧记录。两种来源各自分页，排除本轮/未来消息，不读取私有执行审计。

保持 SQLite schema 3、帧格式 3；不修改人格、主动参与、戳人或生产配置。别名遵守事件保留期（默认7天）及群重置边界，不新增无限期身份存储。规则和工具 schema 改变会建立新上下文段，后续改名只更新请求尾部。

### v2.2.3 戳一戳改动

修复模型将 `[戳一戳事件={...}]` 输出到聊天的问题：动作历史改成明确标注已发生的平台事实，输入不再提供可模仿的戳人标记；读取旧机器人回答及发送时过滤完整事件标记，保留代码示例。格式升到 3，旧帧、段与摘要按需重建一次，不修改原始事件和审计。

核心 `send_message_to_user` 通过本轮 RequestContext 将发往当前会话的消息交给事件发送边界，过滤和真实 ACK 记录同时覆盖工具发送。其他会话仍使用核心原路径，未修改全局 Context 或平台客户端。

增加本轮专用 `native_poke_current_sender` 工具，参数为空，群号与目标从真实事件和回答锚点取得。工具执行真实 `send_poke`，只在成功后记录 action；失败明确返回未确认成功，重复调用不重试，与即时反戳及回复后随机戳人互斥。普通文本不会被转换成平台动作。工具说明稳定，不包含动态群号/账号，只复制本轮 ToolSet。

### v2.2.2 输出格式改动

修复模型把 `message_metadata` 等内部标记当作回答格式输出到群聊。机器人历史现在分成 user 角色的平台记录与 assistant 角色的纯回答正文；引用、@、图片仍由平台记录提供。原始事件和执行审计保留，读取旧回答和生成摘要时清除已泄漏的结构化头。

冻结帧格式升到 2，旧帧按需替换一次；旧段及摘要重建，后续继续稳定追加。SQLite schema 仍为 3，升级不删除原事件、图片或依赖。首次请求的格式前缀会变化，缓存需重新建立。

本轮回复在装饰钩子和事件发送边界过滤完整的内部元数据头（含相邻引用/@标记），普通 JSON、日志文字、行内引用以及代码块示例保留；只有标记没有正文时发送简短格式异常提示。私有生成记录保留原始模型输出，公开历史与框架镜像只记录实际发出的过滤后内容。没有新增模型重试或调用。

### v2.2.1 唤醒与权限改动

补充稳定的平台机器人账号身份，以及请求尾部的明确唤醒/主动参与批准、本轮发送者和回答锚点。明确 @、引用机器人及戳机器人跳过主动判断；纯 @ 补发保留原唤醒来源。正式回复不会再次由人格决定潜水，具体问题先回答或诚实澄清。控制段不写入公共历史，保留稳定前缀。

依据核心实际权限在本轮构建前关闭不可用的计算机 runtime，并复制过滤请求工具集；普通成员不再看到仅管理员可用的 shell 工具和说明。保留管理员权限、主动插话及戳人偏好。此版本没有数据库迁移。

部署时若人格包含“可以不接、已读乱回”等明确问题避答规则，需要同步限定为非明确提问的闲聊。人格由 Dashboard API 单独备份更新，不包含在公开插件仓库，也不自动修改其他使用者的人格。

### v2.2.0 上下文改动

公共群历史只发布实际发送成功的载荷，分段失败不再留下完整生成答案。工具协议单独保存；引用机器人回答能按依赖恢复原问题和关联原图。QQ 的事件局部委托保留平台消息 ID，支持真实引用追溯。

上下文采用持久分段追加，预算换段时批量裁剪并生成带来源的文字摘要；旧引用放请求尾部。人格、工具、模型、角色隔离，保留主动插话和戳人配置。增加分阶段缓存与前缀变化诊断。

## 原地升级

保留插件唯一名称 `astrbot_plugin_group_chat_plus`、`multimodal_v1` 数据目录和已有行为配置，包括主动参与、戳人概率、群名单和模型选择。新增配置有默认值，不要求替换生产配置文件。

刷新首次加载时，在数据库工作线程内将 schema 1/2 升级到 3，迁移前生成 `multimodal_v1/events.pre-v3.sqlite3` 一致性快照。schema 1 的原有 pre-v2 备份仍保留。新增独立执行记录、回合依赖、上下文段和摘要、请求哈希诊断。

旧生成协议先转入执行表；仅将已完整发送的最终 assistant 文字保留为兼容公共记录，工具结果不进入共享历史。旧版未记录逐段载荷，部分/不确定发送无法精确恢复，予以隔离，不猜测公开内容。原事件序号和附件保留。首次旧回答引用可尝试当时同人 120 秒内的图片关联；新版回答使用持久依赖。

生产文件替换前备份原插件目录、配置及 SQLite 一致性快照。替换文件后由使用者在 WebUI 刷新插件，无需重启 AstrBot。文件部署不表示已加载新版本。

## 回滚

v2.2.3 的帧格式为 3，v2.2.2 为 2。两者都会在格式不符时重建派生缓存。回退到更早的 v2.2.1 时，即使 SQLite schema 仍是 3，也应先停止/卸载插件，再清空派生的 `frames` 与 `segments` 表，保留原事件、执行记录、依赖和附件；也可恢复部署前一致性快照，但会丢失快照后的新增记录。不要只换更早代码而继续使用格式 2/3 的缓存。

先停止/卸载该插件以关闭数据库连接，恢复备份插件目录和配置；若已迁移数据，恢复迁移前 SQLite 一致性快照，并清除关闭连接后遗留的对应 WAL/SHM 文件，再刷新旧插件。不得在活动数据库连接上覆盖数据库文件。恢复旧快照会使共享上下文回到快照时间；附件文件无需删除。

## 支持范围

原生文本/图片群聊、引用、合并转发、纯 @ 补发、可选主动插话、QQ 群戳一戳。人格、知识库、工具、权限、停止与正常框架发送继续复用核心。

音视频、文档、私聊、Live/TTS、跨群长期记忆和无消息触发的后台发话不在本次范围内。缓存结构优化已实现，服务端实际命中率不作预估承诺。
