# v2.2.1 升级说明

## 本次改动

补充稳定的平台机器人账号身份，以及请求尾部的明确唤醒/主动参与批准、本轮发送者和回答锚点。明确 @、引用机器人及戳机器人跳过主动判断；纯 @ 补发保留原唤醒来源。正式回复不会再次由人格决定潜水，具体问题先回答或诚实澄清。控制段不写入公共历史，保留稳定前缀。

依据核心实际权限在本轮构建前关闭不可用的计算机 runtime，并复制过滤请求工具集；普通成员不再看到仅管理员可用的 shell 工具和说明。保留管理员权限、主动插话及戳人偏好。此版本没有数据库迁移。

部署时若人格包含“可以不接、已读乱回”等明确问题避答规则，需要同步限定为非明确提问的闲聊。人格由 Dashboard API 单独备份更新，不包含在公开插件仓库，也不自动修改其他使用者的人格。

### v2.2.0 上下文改动

公共群历史只发布实际发送成功的载荷，分段失败不再留下完整生成答案。工具协议单独保存；引用机器人回答能按依赖恢复原问题和关联原图。QQ 的事件局部委托保留平台消息 ID，支持真实引用追溯。

上下文采用持久分段追加，预算换段时批量裁剪并生成带来源的文字摘要；旧引用放请求尾部。人格、工具、模型、角色隔离，保留主动插话和戳人配置。增加分阶段缓存与前缀变化诊断。

## 原地升级

保留插件唯一名称 `astrbot_plugin_group_chat_plus`、`multimodal_v1` 数据目录和已有行为配置，包括主动参与、戳人概率、群名单和模型选择。新增配置有默认值，不要求替换生产配置文件。

刷新首次加载时，在数据库工作线程内将 schema 1/2 升级到 3，迁移前生成 `multimodal_v1/events.pre-v3.sqlite3` 一致性快照。schema 1 的原有 pre-v2 备份仍保留。新增独立执行记录、回合依赖、上下文段和摘要、请求哈希诊断。

旧生成协议先转入执行表；仅将已完整发送的最终 assistant 文字保留为兼容公共记录，工具结果不进入共享历史。旧版未记录逐段载荷，部分/不确定发送无法精确恢复，予以隔离，不猜测公开内容。原事件序号和附件保留。首次旧回答引用可尝试当时同人 120 秒内的图片关联；新版回答使用持久依赖。

生产文件替换前备份原插件目录、配置及 SQLite 一致性快照。替换文件后由使用者在 WebUI 刷新插件，无需重启 AstrBot。文件部署不表示已加载新版本。

## 回滚

先停止/卸载该插件以关闭数据库连接，恢复备份插件目录和配置；若已迁移数据，恢复迁移前 SQLite 一致性快照，并清除关闭连接后遗留的对应 WAL/SHM 文件，再刷新旧插件。不得在活动数据库连接上覆盖数据库文件。恢复旧快照会使共享上下文回到快照时间；附件文件无需删除。

## 支持范围

原生文本/图片群聊、引用、合并转发、纯 @ 补发、可选主动插话、QQ 群戳一戳。人格、知识库、工具、权限、停止与正常框架发送继续复用核心。

音视频、文档、私聊、Live/TTS、跨群长期记忆和无消息触发的后台发话不在本次范围内。缓存结构优化已实现，服务端实际命中率不作预估承诺。
