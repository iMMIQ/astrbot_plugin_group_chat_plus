# v2.1.0 升级说明

## 本次重构

入口仅负责钩子转发；分离会话协调、参与策略、上下文、平台/核心适配和持久化。移除主分支未加载的上游模块与旧测试，归档 tag 为 `archive/pre-refactor-v2.0.2`。

修复排队下一轮漏掉已完成回复、数据库保存完整内联图片、发送回调计数重复及部分交付误判、主动判断漏记 usage。主回复已经产生的 usage 在发送流水线提前关闭时也记录。

上下文固定历史帧、动态扩展置后、按文件内容去重图片；门控预算不再修改主回复选择。SQL 移出事件循环，所有 SQL 由持久化层统一访问。增加队列上限、配置校验、版本迁移、诊断和 CI。

## 原地升级

保留插件唯一名称 `astrbot_plugin_group_chat_plus`、`multimodal_v1` 数据目录和已有行为配置，包括主动参与、戳人概率、群名单和模型选择。新增配置有默认值，不要求替换生产配置文件。

刷新首次加载时，在数据库工作线程内将 schema 1 升级到 2。迁移前使用 SQLite backup API 生成 `multimodal_v1/events.pre-v2.sqlite3`，其中包含旧数据库的完整内容，仅作回滚备份。迁移新增生成的因果关系、独立交付状态、附件实体、固定帧和诊断表；验证旧附件文件后清除活动媒体表中的内联图片载荷，并压缩活动数据库回收旧载荷空间。新捕获的附件始终只记录短来源标识。

生产文件替换前备份原插件目录、配置及 SQLite 一致性快照。替换文件后由使用者在 WebUI 刷新插件，无需重启 AstrBot。文件部署不表示已加载新版本。

## 回滚

先停止/卸载该插件以关闭数据库连接，恢复备份插件目录和配置；若已迁移数据，恢复迁移前 SQLite 一致性快照，并清除关闭连接后遗留的对应 WAL/SHM 文件，再刷新旧插件。不得在活动数据库连接上覆盖数据库文件。恢复旧快照会使共享上下文回到快照时间；附件文件无需删除。

## 支持范围

原生文本/图片群聊、引用、合并转发、纯 @ 补发、可选主动插话、QQ 群戳一戳。人格、知识库、工具、权限、停止与正常框架发送继续复用核心。

音视频、文档、私聊、Live/TTS、长期摘要和无消息触发的后台发话不在本次范围内。缓存结构优化已实现，服务端实际命中率不作预估承诺。
