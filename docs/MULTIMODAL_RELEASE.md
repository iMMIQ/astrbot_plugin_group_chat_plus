# v2.0.1 实现与切换记录

实现日期：2026-10-02。运行入口重写，旧模块保留用于上游对照。

## 已完成的验收

- 组件测试：发图后 3/21/119 秒提问、快速群聊背景、跨人引用优先、当前图不重复、作用域/snapshot、去重/reset、预算、失败附件、重启/清理租约、完整工具角色与 ID、请求扩展保留、旧包装恢复。
- 真实 SDK：经过 conversation.history 重载和 Agent 构建后，模型输入仍含前序原图；人格与 KB 保留；完整回复回写；镜像没有 base64；房间并发串行；纯 @ 只收同人补发。
- 真实 SDK 工具循环：工具调用 ID、结果、工具返回的图片和最终回复保存完整；无最终 assistant 回复的终止工具也保存实际调用结果。
- 严格图片适配：独立请求对象阻止核心去图降级，不修改全局模型对象或 HTTP 客户端所有权。
- 当前 GLM 原生提供商：两张独立红/蓝 PNG 作为历史 user 图片输入，返回“红色，蓝色”。测试只使用程序生成的无敏感测试图。
- 缓存统计接入修正：自管 Agent 执行后调用核心统计写入，保留 `provider_stats` 的输入、缓存、输出及状态统计；真实 SDK 探针验证普通回复、工具多轮和终止工具的累计 token。探针拦截数据库写入，不产生生产统计行。首次部署到修正生效前缺失的 usage 无法补算。

## 对设计的具体调整

1. 框架会话继续按原 UMO 使用，保留已选择的人格和权限。房间共享日志与房间锁提供群连续性，不改写事件 UMO 或用户会话身份。
2. 完成生成后，框架镜像只保留本轮 user/assistant/tool；群历史不在两处竞争。附件标记保留，base64 只存在于请求。
3. 调用 AstrBot 原生 local Agent 的构建和执行路径，复用正常请求/响应/工具/装饰/发送钩子。为避免核心图片降级，提供商只在该请求内克隆；NapCat 输出使用缓冲模式，不接 Live/TTS。
4. 默认总输入预算提高为 32768，给框架人格和工具集合留空间。图片 token 成本仍是保守估算，需结合真实 usage 调整。
5. 阶段 1、2 和主要去重判断的删除已实现；阶段 4 的摘要、音视频、文档、私聊尚未实现。不保留旧版沉默后主动发新话题的后台任务。

## 切换与回滚

生产替换前应备份完整旧插件目录和同名配置文件。保持原插件唯一名称，将代码与精简配置放回原目录，用户通过 WebUI 刷新该插件即可；不重启 AstrBot。

刷新后插件显示为 NativeMM 群聊 v2.0.1。旧概率、情绪、转述、独立面板配置不再生效，群名单和主模型选择按迁移后的配置使用。首次切换使用新接收的消息；已有占位图片无法恢复。

回滚时恢复备份的旧目录和配置，再在 WebUI 刷新插件。新 `multimodal_v1` 日志与旧数据隔离，回滚不需要删除任何历史。

真实 QQ 端到端验证要在刷新后进行：发送新图，再单独 @ 提问，检查回复与 `[NativeMM] ... images=1` 日志。部署文件校验和 SDK 探针不替代用户实际刷新后这一项验证。
