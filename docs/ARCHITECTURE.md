# NativeMM v2.2 架构与行为契约

主分支只维护原生图片群聊实现。上游群聊、私聊及独立 Web 实现保存在 Git tag `archive/pre-refactor-v2.0.2`，许可证及上游署名保留。

## 边界

- `main.py`：AstrBot 事件、钩子和命令转发。
- `multimodal/models.py`：事件、消息段、上下文选择与本轮状态类型。
- `multimodal/conversation.py`：房间队列、生命周期、生成与交付协调。
- `multimodal/participation.py`：概率、冷却及严格 JSON 插话判断。
- `multimodal/context.py`：因果视图、引用/原图保护、轮次预算与固定历史帧。
- `multimodal/segments.py`：按请求策略隔离的公共上下文段、换段摘要和引用补充。
- `multimodal/bridge.py`：保留其他请求扩展，并将动态扩展放到群历史之后。
- `multimodal/adapters/astrbot.py`：唯一的 AstrBot 核心兼容边界；人格、KB、工具、统计、会话镜像与严格图片策略。
- `multimodal/adapters/onebot.py`、`poke.py`：平台消息、引用、转发及戳人动作。
- `multimodal/storage/sqlite.py`：唯一 SQL 入口、版本迁移、事件/生成/交付/帧/诊断。单独线程拥有 SQLite 连接。
- `multimodal/storage/assets.py`：原图文件、下载队列、内容哈希、租约、TTL 与配额。

不新增其他 Agent 框架、后台任务平台或独立 Web 服务。保留 AstrBot 原 UMO、人格选择和权限；房间键含平台实例、bot 和群。

## 上下文

`anchor.seq` 确定本轮成员消息边界。执行视图允许纳入等待期间已发送且触发早于本轮的机器人回复；排除晚于本轮的成员消息。`causal_anchor` 将公开回复与问题作为完整轮次裁剪。工具调用、工具结果和生成的未发送答案仅存 `executions`，按原 UMO 限定读取，不向其他成员的公共历史回放。

保护当前问题、明确引用、同人近期原图。主请求组装后持久化 `turn_links`，引用机器人回答能沿依赖恢复原问题及当时选入的图片；图仍在原事件中，不产生 caption。恢复最多 32 个依赖事件，超过图片或输入预算明确报错。

新段以最近 40 条 / 10 分钟播种。段内起点固定，后续实际可见消息持续追加；段中历史帧按人格/规则、工具 schema、模型及角色指纹隔离。达到约 80% 可用预算，或原有前缀无法完整容纳时，批量保留约 50% 预算的最近完整轮次，并为被移出的文字生成带事件来源的摘要。强制关联内容可能使保留比例更高。摘要最多 12 项 / 配置预算，只在预算换段时更新；无效输出或超时退回带发送者的原文摘录。图片不经过摘要模型。

段空闲 30 分钟后重新播种；附件失效触发换段；事件/摘要来源被清理、房间重置、相关配置改变时旧段失效。`/mmreset` 同时清除本群段和依赖。首次加入或权限/人格不同的请求使用各自的段。迟到触发不会读入较新的段。

数据库只存 `journal_image` 引用，请求时恢复原字节并按 SHA 去重。引用段外旧消息和旧帧遗漏/尚未下载的当前关联图片仅进入本轮尾部补充，避免重写历史前缀。组装及 Agent 执行持有附件租约。

请求顺序：人格/规则/工具 → 摘要及固定公共历史（含当前消息的规范帧）→ 框架动态扩展 → 当前触发 ID、旧引用及动态补充。当前问题转入下一轮历史时保持相同结构。其他插件整体覆盖 contexts 仍需明确所有权。主动插话保留原有开关、概率及冷却；判断使用 4096 token 小预算，不提交主请求段。

## 生成与交付

生成状态：`running/generated/failed/uncertain`。交付状态单独记录：`pending/sent/partial/none/uncertain`。

核心分段发送会捕获单段异常，并仍触发发送后钩子，因此钩子不能证明成功。本轮事件的 `send` 被临时追踪：实际发送前记录尝试，成功后记录收据及实际发送载荷，异常记录失败；QQ SDK 的 `send()` 丢弃平台返回 ID，因此给当前事件提供独立 bot 委托，捕获实际 `send_group_msg` / 群转发 ACK，并关联后续引用。退出时恢复该事件的方法和 bot 引用；共享客户端不修改。平台成功后的持久化失败仅记诊断，不引发重发。钩子仅用于后续动作且去重，不能制造成功。

已成功发送后提前关闭/取消，或正常结束但有失败段，记 `partial`；正常结束且实际尝试全部成功才记 `sent`；没有发送尝试记 `none`；失败或结果未知记 `uncertain`。SDK 不一定返回平台消息 ID，不能保证跨进程 exactly-once，未知发送结果不自动重发。回复后戳人独立保证每轮最多尝试一次，并要求实际发送成功。

每群运行和等待总数默认 8，排队超时 120 秒；下载队列默认 128，并发 4。刷新取消入库/生成任务，等待附件和数据库工作线程完成，再关闭资源。未完成生成重载后标记不确定，禁止自动重放。

纯 @ 按同人到达时间收补发，等待已到达消息入库；其他成员不能成为本轮触发者。

## 统计

主动判断、主回复和摘要压缩均进入核心 provider stats；主回复统计包含工具多轮和发送阶段提前关闭时已经产生的 usage。插件另按 `gate/reply/summary` 保存输入/缓存/输出 token、耗时、图片数、选择/淘汰数量和附件失效次数。`/mmstatus` 返回分阶段输入/缓存/未缓存累计、平均耗时和最近请求诊断。请求诊断存 system/tools/history 哈希、消息哈希、公共前缀长度和首个变化位置/原因；不保存诊断原文或图片载荷。统计仍是一次 Agent 执行的汇总，工具多轮不冒充独立 wire 调用，哈希前缀也不是服务端实际缓存命中。

## 兼容约束与回归

真实 SDK 契约固定 AstrBot v4.28.2、本地 Agent、NapCat/aiocqhttp 缓冲回复。公开 `tool_loop_agent()` 不等价于完整流水线，因此暂保留核心构建器；核心内部依赖全部限于 `adapters/astrbot.py`。Provider 图片失败不得悄悄去图重试。

CI 运行 Ruff、组件回归和固定核心版本的离线 SDK 探针。探针调用真实构建器、钩子和工具执行器，模型、平台和统计落库被拦截。真实 QQ 收发和服务端缓存改善需刷新后观察。
